# Architecture

The package has three owned layers and two generated output directories.

```text
src/                         TypeScript validation and public API
        | dynamic import
        v
wasm/                        generated wasm-bindgen loader and binary
        | calls
        v
crates/opencv-wasm/src/      Rust pixel operations

parity/manifest.ts           typed compatibility source
        | generated by script
        v
docs/parity.json             machine-readable compatibility report
```

## TypeScript boundary

`src/image.ts` owns image validation. The client checks data before invoking WASM and validates each returned buffer by constructing a new `RgbaImage`. `src/wasm.d.ts` describes the generated wasm-bindgen module without checking generated files into Git.

`initOpenCv()` uses the package-private `#wasm` import. `package.json` maps that name to the generated loader. The compiled JavaScript keeps this import, so a consumer's bundler resolves it inside the installed package.

## Rust core

`crates/opencv-wasm` separates exported wrappers from pure image functions. Unit tests execute the pure functions on the native Rust target. wasm-bindgen translates exported `Result<Vec<u8>, JsError>` values into JavaScript values and exceptions.

The crate forbids unsafe Rust. Release builds optimize for binary size, use link-time optimization, and abort on panic. Invalid user input returns an error before allocation or indexing.

The current Rust compiler emits bulk-memory instructions that the optimizer bundled with wasm-pack 0.15 cannot validate. The crate disables that extra `wasm-opt` pass. Cargo still applies size optimization and link-time optimization. Re-enable `wasm-opt` only after its bundled Binaryen build accepts the emitted module in CI.

## Matrix and compute design

The Rust `Mat` owns raw scalar bytes through `Arc<[u8]>` and records one of the seven OpenCV scalar depths from U8 through F64. A region of interest clones the allocation handle and stores its own offset, dimensions, and byte stride. Region creation does not copy pixels. Copying occurs only when data enters WASM or a caller requests a compact typed-array export.

The TypeScript `Mat` owns one wasm-bindgen handle and requires `dispose()`. It does not use finalization as the lifetime mechanism. This keeps release timing deterministic and lets a region survive disposal of its parent handle.

CPU scalar Rust remains the correctness implementation. SIMD kernels will use WASM SIMD after differential fixtures exist. Threaded builds require cross-origin isolation and a worker pool, so the loader must keep a single-thread fallback. GPU work will use a separate WebGPU adapter only after a real GPU kernel exists and beats CPU execution after upload and dispatch costs. Until then, adding a generic compute seam would be hypothetical.

## Build outputs

`bun run build` deletes and rebuilds only `dist/` and `wasm/`.

- `wasm-pack` compiles Rust for `wasm32-unknown-unknown` and writes the loader, declarations, and binary to `wasm/`.
- TypeScript writes ESM, declarations, declaration maps, and source maps to `dist/`.
- The build loads the finished WASM binary and runs a known grayscale input through its generated JavaScript ABI.
- npm includes both directories through the `files` allowlist.

## Compatibility accounting

`parity/upstream-inventory.ts` owns the 488-family denominator. `parity/manifest.ts` records planned, partial, and fully implemented package work against unique inventory IDs. `bun run parity:write` updates `docs/parity.json`. `bun run parity:check` compares supported entries with TypeScript metadata, every Rust source export, the README, and the generated JSON. This catches accounting drift. It does not prove numeric equivalence with OpenCV. Golden fixtures and differential tests remain required before a family becomes fully implemented.
